# Phase 6 データ・バックアップ・診断

WebUI またはデスクトップ版で **表示設定 → データとバックアップ** を開きます。

## エクスポートとインポート

**バックアップを書き出す** を選ぶと、形式バージョン、ファイルサイズ、
SHA-256 を記録した ZIP が作成されます。既定では設定、監視タスク、価格通知、
旅行リスト、柔軟日程タスクが対象です。履歴を有効にすると、価格、通知、
イベント、タスク実行履歴も追加されます。共有用バックアップから通知・メール
の認証情報は除外されます。

インポートでは最初に **インポートを確認** を実行します。パス、サイズ、
マニフェスト、全 SHA-256、SQLite 整合性、主キー競合を確認してから実行ボタン
が有効になります。競合時は「既存を保持」「バックアップで上書き」
「バックアップに含まれるデータを置換」から選択します。

適用前に完全なロールバック ZIP が自動作成されます。DB は一時コピーで更新し、
整合性と外部キーを検証した後に原子的に交換します。柔軟日程検索が実行中の
場合は先に一時停止してください。

## 更新バックアップ、整理、診断

デスクトップ更新は SHA-256 と署名者の一致を確認後、アプリを置換する前に
完全バックアップを作成し、`rollback.json` にバージョン、資産名、アプリと
データの復元情報を記録します。

ストレージ画面では保存場所、DB サイズ、Schema、テーブル件数を確認できます。
整理は選択したキャッシュ・履歴だけを対象とし、主要タスク、ルール、旅行
リスト、設定、最新バックアップを保持します。

診断レポートとサポートバンドルは DB、書き込み権限、OS/CPU、Python、依存関係、
実行状態を確認します。認証情報は自動で秘匿化され、バンドルには独立した
マニフェストと SHA-256 が付きます。
